# 2.0.1 - a pipeline driver, and a resume that verifies

Foundation work. No scientific behaviour changed: the machinery for running studies arrived before
any default moved, so the two could be reviewed separately.

## What's new

- **`metawrap2 run <sheet|directory>`** runs a whole study from a small TOML or YAML sample sheet.
  It owns the intermediate layout and the plumbing between steps, which the tutorial previously
  had users do by hand with `mkdir`/`mv`/`cat`.
- **A `--resume` that verifies.** A step is skipped only if it completed, its outputs are present
  and non-empty, and none of its inputs has changed. `metawrap2 status` shows what a resume would
  do before it runs.
- **A durable run history.** `metawrap2 history` records every run started on this machine,
  outside any output directory, and `--diff` compares two of them.
- **One naming convention for bins**: `bin_001.fasta`, with statistics tables as `*.stats.tsv`.
- **One-command install**: `metawrap2 quickstart` builds the environments and verifies them.

## Defaults that moved

None.

## Known issue, fixed in 2.1.2

`install-env` could not reach three environments (bakta, checkm2, gtdbtk) under any name, because
it read only one of the four registries that map a name onto an environment. On 2.0.x, create those
three by hand with `mamba env create -f <envs>/<name>.yaml`. See
[2.1.2](2.1.2.md#9-correctness-fixes-with-numbers-attached).
