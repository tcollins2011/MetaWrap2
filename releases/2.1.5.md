# 2.1.5 - presets `default` and `deep`, fixes from a new-user test

The listed binning presets are now `default` and `deep`; `deep` is the preset 2.1.4 called `gpu`.
Most of this release fixes what a second new-user test of 2.1.4 found: a full three-sample `cohort`
run on an environmental dataset, plus most modules and utilities around it.

| | 2.1.4 | 2.1.5 |
|---|---|---|
| three-binner preset | `--preset gpu` (`slow` still accepted) | `--preset deep` (`gpu` and `slow` still accepted) |
| presets in `binning --help` | five names | `{default,deep}` |
| concurrent GPU steps in `cohort -j N` | all on the first card | one card each |
| missing database in a `run`/`cohort` | fails at its step, possibly hours in | stops before the first step |
| `--dry-run` then `--resume` | could report a finished step that never ran | dry runs write no step markers |
| database paths | conda env variables, lost when an env is rebuilt | passed to each tool from the config |
| a failed tool | Python traceback | the tool, its exit code and the end of its error output |

## Changed

- `--preset gpu` is renamed `--preset deep`. It runs the same binners (metaBAT2, SemiBin2 and
  COMEBin) and trains SemiBin2 and COMEBin with `--device cuda` unless `--device` is given. If
  binners are named explicitly, the preset and its device default are ignored.
- `--preset gpu` and `--preset slow` still work as aliases of `deep`, on the command line and in
  study sheets.
- `binning --help`, the error for a run with no binner, and the error for an unknown preset list
  `default` and `deep`.
- `--preset fast` and `--preset very-fast` are no longer documented; they still run.

## Fixed

- **Global flags in studies.** Flags typed before `run`, `cohort` or `benchmark` (the resource
  limits such as `--max-disk-fraction`, and `--skip-space-check`, `--skip-validation`,
  `--verbose-logs`, `--heartbeat-seconds`, `--gpu-strict`) were applied to the driver but not to
  the steps it starts. They now reach every step, which still gets its own share of threads and
  memory (issue #6).
- **Intermittent `quickstart` failures.** Environments built in parallel share conda's package
  cache, and concurrent writes could leave a truncated channel index or a missing package archive.
  The first environment is now built alone, and any environment that fails during the parallel
  builds is retried on its own. `-t 1` builds everything serially (issue #5).
- **Tests and temporary paths.** Banners wrap long lines and frame them with `*****`, so a temporary
  path of some lengths split the phrase a test matched. Tests now strip the frame before matching.
- **Lockfiles.** The reads, annotate and taxonomy lockfiles lacked Flye, Nonpareil, dbCAN, GECCO and
  Bracken, so `install-env --from-lock` built environments without them. They are re-solved, and a
  test checks every lockfile against its yaml.
- **Scheduled workflows.** The fresh-solve and end-to-end jobs ran `read_qc` without a host
  database; they now pass `--skip-bmtagger`.

## New

- **`metawrap2 check --for "<command>"`** reports exactly the databases and conda environments
  one module command needs, then `ready: yes` or `ready: no (N missing)`, with the `install-db`
  command for each missing database.
- **`install-db --for <module>` and `--for-sheet <samples.toml>`** install the databases a module,
  or every step a sample sheet plans, needs. The sizes and the total are shown first.
- **`install-env` and `quickstart`** print which environments are still building after each one
  finishes.
- **Costs in `provenance.txt`.** Each step in a module's `provenance.txt` has its CPU time, wall
  time and peak memory. A `run` or `cohort` study writes its own `provenance.txt` with the catalogue
  strategy, every step's cost and the totals.
- **Weekly fresh-solve check of every default environment.** CI solves each environment from its
  yaml, without the lockfile, and runs its tools; the opt-in environments are checked monthly. A
  dependency that moves upstream now shows up there instead of on a user's first install.

## Fixed: from the new-user test

- **Environments that broke on new library versions.** GTDB-Tk 2.4 does not run on Python 3.13
  or later or on numpy 2, and argNorm (in `amr`) does not run on pandas 3. `gtdbtk.yaml` and
  `amr.yaml` now pin them. The GTDB-Tk lockfile, which held the broken versions, is removed until
  it is re-solved. A test checks that every lockfile agrees with its yaml.
- **GTDB-Tk's failure hint** no longer blames the database when GTDB-Tk had already loaded it.
- **Database paths reach the tools.** Paths set in the config (GTDB-Tk, CheckM, CheckM2, CheckV,
  Bakta) are passed to each tool's process, so rebuilding an environment no longer loses them.
- **`check` and `doctor`.** A database is called optional only when a flag lets the module run
  without it, and the label names that flag. `check viruses` without geNomad's database fails.
  `check <module>` lists only that module's databases. `doctor` says which modules it covers
  (`--all` for every module), and its counts match its rows.
- **Databases are checked before a study starts.** `run` and `cohort` work out which databases the
  planned steps and sheet flags need and stop before the first step if one is missing.
- **`--dry-run`.** A dry run writes no step markers and decompresses nothing, and a following
  `--resume` cannot mistake it for finished work. The real run into the same directory is no longer
  refused as "already exists". `run --dry-run` and `cohort --dry-run` create nothing at all.
- **GPUs under `cohort -j N`.** Concurrent learned-binner steps each get their own card, within
  `--max-gpus`, and the step banner names them. Before, all ran on the first card.
- **Spaces in paths.** Every module, CheckM, CheckM2, GUNC and external benchmark arms now pass
  each path to the tool as one argument, so an output directory with a space in its name works.
- **Compressed reads with the wrong name.** A gzip or bzip2 file not named `.gz`/`.bz2` is reported
  with the rename to make, instead of failing inside FastQC.
- **Tool failures** end with the tool, its exit code and the last lines of its error output; the
  Python traceback is shown only with `--verbose-logs`. Non-UTF-8 bytes in a tool's output no longer
  stop the run.
- **`phylogeny`** reads gzipped alignments, such as GTDB-Tk's `*.user_msa.fasta.gz`.
- **False "already exists" warning** on a fresh output directory in `read_qc`, `assembly`, `kraken2`
  and `reassemble_bins`.
- **`install-db`** honours `[limits] max_disk_fraction`, counts the unpacked size for databases
  whose archive is removed after unpacking (GTDB-Tk needs twice its size), explains downloader exit
  codes, waits longer between retries when a server refuses connections, and names
  `bin_refinement --skip-gunc` when GUNC's database cannot be downloaded.
- **`score`** accepts `--skip-gunc` and `bin_refinement` accepts `--no-gunc`. `score` exits 1 when
  it finds no genomes, and `score -x 10` explains that `-x` is the file extension there.
- **Smaller fixes.**
  - `metawrap2 completion` accepts only `bash` or `zsh`, and `-h` works.
  - `config init` puts each explanation above its key.
  - `diff_abundance` accepts `-t`.
  - The cost line shows `n/a` for steps under 5 s, and the share of the thread grant used.
  - `--single-end` on an interleaved file gives a warning.
  - The geNomad error names `--genomad-db`.
  - The example sample sheet says it is read once, when the run starts.
  - Plain-file benchmark datasets are fetched to the folder `benchmark run` reads.

The low-retention warning in `read_qc` now names long reads, where quality decays along the read,
as a common cause. The tester's dataset (a thiocyanate bioreactor, 2x251 bp) is registered in
`benchmarks/datasets.toml` for the `trimmer` comparison. On it, Trim Galore kept 32.6% more reads
and 17.9% more Q30 bases than fastp and used 21% less CPU. The default stays fastp, because the
CAMI2 benchmarks are simulated, high-quality reads, where fastp's filtering costs nothing; the
warning tells users with lower-quality data what to switch.

None. `default` (metaBAT2 + SemiBin2) is still the preset `metawrap2 run` uses.
